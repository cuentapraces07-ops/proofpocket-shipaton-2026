## Product angle

**ProofPocket for independent operators**: a focused workspace that turns a scattered request into an auditable work packet: objective, acceptance checklist, evidence checkpoints, owner, due date and a ready-to-send payout report.

This is a real workflow rather than a generic chatbot. The prototype already has the core state model and the most important integrity behavior: it distinguishes potential value from paid value and visibly marks incomplete/unverified evidence.

## Submission strategy

1. Use the existing local prototype as the product specification, but rebuild/deploy the contest version inside Emergent so the platform use is genuine.
2. Demonstrate one concrete before/after workflow: a builder receives a request, records the acceptance condition, attaches evidence, and exports a concise handoff.
3. Show measured local outcomes only if they are actually observed; never claim customers, revenue, or time saved without evidence.
4. Submit early enough to receive a confirmation email and a `Submitted` status. Deployment alone does not count.
5. If the entry is submitted, only share its official public link through channels the owner explicitly authorizes. No bots, bought votes, fake accounts, vote swapping or invented engagement.
